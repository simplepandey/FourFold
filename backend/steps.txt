PART 4 — FIREWALL — LOCK DOWN POSTGRES
Postgres on the open internet with just a password is a bad idea. Restrict port 5432 to only the IPs that legitimately need it (your backend server, your laptop).

Step 10 — Base Firewall Rules

ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
Step 11 — Allow Postgres Only From Trusted IPs
Replace YOUR_BACKEND_IP and YOUR_LAPTOP_IP with real IPs (curl ifconfig.me on each machine to find them):


ufw allow from YOUR_BACKEND_IP to any port 5432 proto tcp
ufw allow from YOUR_LAPTOP_IP to any port 5432 proto tcp
If your laptop's IP changes often (home ISP, no static IP), you'll need to re-run this each time you want to connect directly from your laptop. Alternative: skip laptop access here and use ssh port-forwarding instead (Step 20).

Step 12 — Enable Firewall

ufw enable
Type y when warned about disrupting SSH.

Step 13 — Verify

Expected:

5432/tcp                   ALLOW       YOUR_BACKEND_IP
5432/tcp                   ALLOW       YOUR_LAPTOP_IP
PART 5 — RUN POSTGRES
Step 14 — Create a Project Directory

mkdir -p /opt/fourfold-db
cd /opt/fourfold-db
Step 15 — Generate a Strong Password

openssl rand -base64 24
Copy the output — this is your POSTGRES_PASSWORD.

Step 16 — Create .env

nano .env
Paste (replace the password with what you generated):


POSTGRES_USER=fourfold_app
POSTGRES_PASSWORD=PASTE_GENERATED_PASSWORD_HERE
POSTGRES_DB=fourfold_db
Save: Ctrl+X → Y → Enter.

Step 17 — Create docker-compose.yml

nano docker-compose.yml
Paste — this is a slimmed-down version of your project's own backend/docker-compose.yml, just the postgres service, standalone on this VPS:


services:
  postgres:
    image: postgres:15-alpine
    container_name: fourfold-postgres
    restart: unless-stopped
    ports:
      - '5432:5432'
    env_file:
      - .env
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U $$POSTGRES_USER']
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  postgres-data:
restart: unless-stopped is the key line — it survives VPS reboots without any systemd unit needed.

Save: Ctrl+X → Y → Enter.

Step 18 — Start It

docker compose up -d
Expected:

Step 19 — Verify It's Healthy

docker compose ps

PART 6 — CONNECT
Step 20 — Test From Your Laptop
If your laptop's IP is in the firewall allowlist (Step 11):


psql "postgresql://fourfold_app:YOUR_PASSWORD@YOUR_DB_SERVER_IP:5432/fourfold_db" -c "\conninfo"
If not allowlisted (or IP changes often), tunnel over SSH instead — no firewall change needed since it rides on port 22:


ssh -L 5433:localhost:5432 root@YOUR_DB_SERVER_IP
# in a second terminal:
psql "postgresql://fourfold_app:YOUR_PASSWORD@localhost:5433/fourfold_db" -c "\conninfo"
Step 21 — Point the Backend At It
Wherever NestJS runs, update backend/.env:


DATABASE_URL=postgresql://fourfold_app:YOUR_PASSWORD@YOUR_DB_SERVER_IP:5432/fourfold_db
(No ?sslmode=require needed here — this container doesn't have TLS configured, unlike Vultr Managed Database. Fine for a locked-down firewall setup; see Step 24 if you want TLS too.)

PART 7 — (OPTIONAL) ADD TLS
If your backend connects over the public internet (not a private VPC), consider encrypting the connection. Reuse the same Let's Encrypt approach as your EMQX guide, but for Postgres:

Step 24 — Get a Cert (needs a domain pointed at YOUR_DB_SERVER_IP)

apt install certbot -y
certbot certonly --standalone -d db.yourdomain.com
Step 25 — Mount Certs Into the Container

mkdir -p /opt/fourfold-db/certs
cp /etc/letsencrypt/live/db.yourdomain.com/fullchain.pem /opt/fourfold-db/certs/server.crt
cp /etc/letsencrypt/live/db.yourdomain.com/privkey.pem /opt/fourfold-db/certs/server.key
chmod 600 /opt/fourfold-db/certs/server.key
chown 999:999 /opt/fourfold-db/certs/server.key   # postgres user inside the alpine image
Add to docker-compose.yml under the postgres service:


    volumes:
      - postgres-data:/var/lib/postgresql/data
      - ./certs:/var/lib/postgresql/certs:ro
    command: >
      postgres
      -c ssl=on
      -c ssl_cert_file=/var/lib/postgresql/certs/server.crt
      -c ssl_key_file=/var/lib/postgresql/certs/server.key

docker compose up -d
Then use ?sslmode=require in DATABASE_URL.

PART 8 — BACKUPS
Step 26 — Manual Dump

docker exec fourfold-postgres pg_dump -U fourfold_app fourfold_db > /opt/fourfold-db/backup-$(date +%F).sql
Step 27 — Automate With Cron

crontab -e
Add (daily at 2 AM, keeps backups in /opt/fourfold-db/backups/):


0 2 * * * mkdir -p /opt/fourfold-db/backups && docker exec fourfold-postgres pg_dump -U fourfold_app fourfold_db > /opt/fourfold-db/backups/backup-$(date +\%F).sql && find /opt/fourfold-db/backups -mtime +7 -delete
This keeps 7 days of backups and deletes older ones automatically. For anything you actually care about long-term, copy these off-server too (e.g. rsync to another machine, or upload to Vultr Object Storage / S3).

Step 28 — Restore From a Backup (if needed)

cat /opt/fourfold-db/backups/backup-2026-08-01.sql | docker exec -i fourfold-postgres psql -U fourfold_app fourfold_db
USEFUL COMMANDS REFERENCE

docker compose ps                          # status
docker compose logs -f postgres            # live logs
docker compose restart postgres            # restart
docker compose down                        # stop (keeps volume/data)
docker exec -it fourfold-postgres psql -U fourfold_app fourfold_db   # shell into DB
df -h                                       # disk usage

COMMON ERRORS AND FIXES

ERROR: connection refused from backend
FIX:   Backend's IP isn't in the ufw allowlist (Step 11).
       Re-check: ufw status

ERROR: password authentication failed
FIX:   .env POSTGRES_PASSWORD doesn't match what's in DATABASE_URL,
       or you edited .env after the container already initialized
       the volume — password changes in .env only apply on first
       container creation. To force it: docker compose down -v
       (⚠ this deletes all data) then docker compose up -d again.

ERROR: docker compose ps shows "unhealthy"
FIX:   docker compose logs postgres — usually a bad POSTGRES_USER/
       POSTGRES_PASSWORD/POSTGRES_DB combo, or disk full (df -h).

ERROR: container doesn't survive reboot
FIX:   Confirm `restart: unless-stopped` is in docker-compose.yml
       and that docker itself is enabled: systemctl enable docker

ERROR: "FATAL: no pg_hba.conf entry" after adding TLS
FIX:   Client needs sslmode=require in the connection string once
       ssl=on is set on the server.

PART 7 — HTTPS VIA NGINX + LET'S ENCRYPT
Your Flutter app's AppConfig already expects https://dev-api.aquacontrol.in and https://api.aquacontrol.in — point one of those at this server.

Step 14 — DNS

Add an A record:
  Name:  dev-api  (or api, for prod)
  Value: YOUR_API_SERVER_IP

Full domain: dev-api.aquacontrol.in → YOUR_API_SERVER_IP
Wait for propagation, verify:

Step 15 — Install Nginx + Certbot

apt install -y nginx certbot python3-certbot-nginx
Step 16 — Configure the Reverse Proxy

nano /etc/nginx/sites-available/fourfold-api

server {
    listen 80;
    server_name dev-api.aquacontrol.in;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

ln -s /etc/nginx/sites-available/fourfold-api /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx
Step 17 — Get the Certificate

certbot --nginx -d dev-api.aquacontrol.in

COMMON ERRORS AND FIXES

ERROR: 502 Bad Gateway from Nginx
FIX:   Container isn't running / crashed. Check:
       docker compose -f docker-compose.prod.yml logs api

ERROR: PrismaService fails to connect on boot
FIX:   DB VPS firewall doesn't have this server's IP allowed yet
       (Part 3, Step 6), or DATABASE_URL in .env is wrong.

ERROR: certbot fails "Challenge failed"
FIX:   DNS hasn't propagated yet, or port 80 isn't open
       (ufw allow 80/tcp) — certbot needs HTTP first to issue the cert.

ERROR: MqttService stuck "Reconnecting..."
FIX:   Check MQTT_HOST/USERNAME/PASSWORD in .env match what's set up
       on the EMQX VPS, and that EMQX's firewall allows this
       server's IP on 1883 if you locked that down too.

ERROR: git clone permission denied (publickey)
FIX:   The deploy key (Step 7) wasn't added to GitHub, or was added
       as write-only when your workflow needs read (should be fine
       either way for cloning — check it was added at all).
